# Source

- Course: `10Pines-Capacitacion/C6 - Construccion de Software Seguro usando Test Driven Development` (Dropbox). The first import (statement only) had access to `ArchivosParaTarjetaUSB/C6-ConstruccionDeSoftwareRobustoConTDD/EjercicioTusLibrosV2.pdf` and the 145-slide deck; this second pass had the whole course directory (`TusLibros/` and `Smalltalk/`).
- Statement: `TusLibros/EjercicioTusLibrosV3.pdf` (2 pages, PDF dated 2017-08, `.doc` dated 2016-04), copied as `spec-original.pdf` and translated completely to `spec.md`. `TusLibros/TusLibrosExcercise.pdf` (English, 2021) is copied as `spec-english-original.pdf`; it is a translation of **V2**, not of V3, so its wording was used only for the parts V3 shares with V2 (Merchant Processor interface, the five REST resources, the HTTP 200/400 rule) and the rest was translated. Text was extracted with macOS PDFKit; the `.doc` files with `textutil`.
- Differences between V2 (`EjercicioTusLibrosV2.pdf`, the previous `spec-original.pdf`) and V3:
  - V2 opened with an "upgrade plan" (an existing batch system, stage 1 REST API + on-line Merchant Processor, stage 2 replacing the batch system by reading/writing its files). V3 replaces it with "two sales channels, on-line REST and batch files, both paid by credit card validated with an external Merchant Processor".
  - V3 adds two paragraphs: authentication is very important in the REST interface because it is open to the public (no IP/MAC filtering); the batch interface does not need it because files arrive by email and a person checks the sender.
  - V3 drops the V2 paragraph "the Merchant Processor's up-time is not very good; if it is down, save the transaction to a file for batch processing".
  - V3 adds the specification of the batch files (`CLIENTE_INPUT_AAAA_MM_DD.csv` with record types 1 = add to cart and 2 = check out; `CLIENTE_OUTPUT_AAAA_MM_DD.csv`; the TEMATIKA example). The PDF's output example has one line; the `.doc` has a second one (`2,INVALID EXPIRATION DATE`). The result codes of the example (1, 2) contradict the text (0, 1); reported as a translator's note in `spec.md`.
  - Minor wording: "solo usar el ambiente de desarrollo del merchant processor luego de la integración" became "... en el ambiente de integración del sistema que estamos desarrollando"; "La interfaz Rest" became "La interfaz on-line REST". The rest (Merchant Processor parameters, example URL, the five resources, HTTP rule) is identical.
  - Also in the directory: `TusLibros/EjercicioTusLibros.pdf` (dated 2018-03, no version suffix). It is **not** V3: it keeps V2's upgrade-plan intro and adds the batch-file section, changes the Merchant Processor's success answer to `0|OK`, and says that when the Merchant Processor is down the request must be written to an input file whose customer id is `TUSLIBROS`. It is left out per the task (V3 is the statement); noted here as an open point in case it is the version currently taught.
  - `TusLibros/Resolucion de TusLibros.doc` (2014) holds the instructor's notes for solving it (four sets of tests and design decisions); they were used to check the iteration scopes and are quoted in the iteration specs.
- Slides: no slide defines TusLibros or its iterations. Related slides: 8 (course structure), 119-128 (test doubles; 125-126 show the Cashier/MerchantProcessor stub example), 129-133 (testing techniques, passing of time), 140 (two sides of an interface).
- Code: `Smalltalk/C6-TusLibros-Iteracion1/TusLibros-1.st` .. `-18.st`, `Iteracion2/TusLibros-19.st` .. `-29.st`, `Iteracion3/TusLibros-30.st` .. `-33.st`, `Iteracion4/TusLibros-34.st` .. `-78.st`: consecutive snapshots of the solution built in class (Squeak/Pharo chunk format, CR line endings, ISO-8859-1 with only a form feed as non-ASCII byte; stamps 2013-06, some 2014-10 and 2015-06). `solution/TusLibros-78.st` is the final solution (categories `TusLibros-Model` and `TusLibros-Tests`); the per-iteration starting/solution files and the whole step sequence are in `exercises/10pines-c6-tuslibros-iteracion1` .. `-iteracion4` (`solution/steps/`). Snapshots 74-78 are not one monotonic sequence: 74-75 split the categories, 76 and 77 are alternative endings in category `TusLibros` (76 names the facade `TusLibrosSystemFacade`, 77 `InterfaceRest`), and 78 combines the rename, the category split and the 2015 changes; 78 is taken as the final one.
- Iteration boundaries were determined from the last snapshot of each directory (see the "Iterations" section of `spec.md` and each iteration's `spec.md`); the previous guess (iteration 3 = client interface, iteration 4 = sessions + string protocol + HTTP + batch) was wrong and has been corrected: iteration 3 is the Merchant Processor simulation and iteration 4 is the object facade with sessions and clock; no snapshot implements the string encoding, HTTP or batch files.
